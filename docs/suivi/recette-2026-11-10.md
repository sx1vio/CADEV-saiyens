## 2. Actions infrastructure (responsable infra)

À faire sur le VPS (`/srv/devhub/.env`) et chez name.com, puis redéployer. Liste prête à transmettre.

### 2.1 E-mails transactionnels (FONC-03, majeure)

1. Ouvrir un compte chez un fournisseur SMTP transactionnel (Brevo, Mailjet, Amazon SES ; ou la messagerie pro Systalink si elle autorise l'envoi applicatif).
2. Dans `/srv/devhub/.env` : `SMTP_HOST`, `SMTP_PORT` (587), `SMTP_USER`, `SMTP_PASSWORD`, `MAIL_FROM="DevHub Africa <notifications@devafrica.tech>"`.
3. DNS de `devafrica.tech` chez name.com. **Avant le premier envoi**, sinon tous les e-mails sont rejetés :
   - SPF : remplacer `v=spf1 -all` par celui du fournisseur, par exemple `v=spf1 include:spf.brevo.com -all` ;
   - DKIM : ajouter les enregistrements (CNAME ou TXT) donnés par le fournisseur ;
   - DMARC : garder `_dmarc` en `v=DMARC1; p=reject; rua=mailto:<adresse>` une fois SPF et DKIM alignés (ou passer quelques jours par `p=quarantine`).
4. Redéployer, puis ouvrir **admin.devafrica.tech → Supervision** : « E-mails (SMTP) » doit passer à `ok`.
5. Rejouer « Mot de passe oublié » de bout en bout avec le compte de test : réception, lien, nouveau mot de passe, connexion.

### 2.2 Clés de services (FONC-03)

- `PAGESPEED_API_KEY` : Google Cloud → API « PageSpeed Insights API » → identifiants → clé API (gratuite, 25 000 audits par jour). Sans elle, le pré-vol saute souvent l'audit Lighthouse.
- `LLM_API_KEY` plafonnée : sans elle, la piste IA, les tâches IA et la traduction passent sur le modèle de secours.

### 2.3 TLS de l'origine (gate de la recette)

Lancer https://www.ssllabs.com/ssltest/analyze.html?d=devafrica.tech : attendu A ou A+, TLS 1.0 et 1.1 refusés, TLS 1.2 et 1.3 acceptés. Faire de même pour `admin.devafrica.tech` et `business.devafrica.tech`.

### 2.4 Variable de dépôt `CONTACT_EMAIL`

`gh variable set CONTACT_EMAIL --body "<adresse>"` (dépôt `sx1vio/CADEV-saiyens`). Elle sert à la page Confidentialité et, depuis cette PR, au `security.txt`. Prise au déploiement suivant.

### 2.5 Déploiement

La fusion sur `main` redéploie automatiquement. Ce lot change l'image web (Caddyfile : `precompressed br`) et l'API : vérifier que les deux conteneurs ont bien été reconstruits (§4).

## 4. Vérifier après le déploiement

```bash
# SEC-01, SEC-04 : plus de X-Powered-By, et no-store sur les réponses privées
curl -sI https://devafrica.tech/api/v1/me | grep -iE 'x-powered-by|cache-control'
# même titre 404 pour une route inconnue et une route masquée
curl -s https://devafrica.tech/api/v1/route-inexistante; echo
# FONC-02 : 200 et {"user":null} pour un visiteur
curl -s https://devafrica.tech/api/v1/me/session; echo
# SEC-02, PWA-01
curl -s https://devafrica.tech/.well-known/security.txt
curl -sI https://devafrica.tech/favicon.ico | grep -i content-type
curl -s https://devafrica.tech/manifest.webmanifest | grep -o '"id":"/"'
# NET-01 : Brotli
curl -sI -H 'Accept-Encoding: br' https://devafrica.tech/ | grep -i content-encoding
```

Puis lancer un pré-vol sur https://devafrica.tech : la carte « Recette » doit montrer les gates passées (sauf IDOR, non évaluable) et `sec.api_disclosure`, `pwa.manifest` et `net.brotli` au vert.

## 5. Pré-vol : contrôles de recette intégrés

Demande du responsable infra : intégrer au pré-vol les contrôles pertinents du skill `recette-qa`. Fait dans la PR `feat/prevol-recette-qa`, guide à jour : [prevol.md](../guides/prevol.md#verdict-de-recette-go--no-go).

- **Verdict de recette** sur chaque rapport : GO / GO sous réserves / NO-GO, gates éliminatoires, score par section (barème web / PWA), réserves classées, liste de ce qui reste à tester à la main.
- **Nouveaux contrôles** : pages du sitemap (`func.pages`), routes découvertes (`func.routes`), console au chargement (`lh.console_errors`), routes d'API sans session (`sec.anonymous_api`), divulgation de la pile (`sec.api_disclosure`), zoom (`a11y.zoom`), langue (`a11y.lang`), manifeste (`pwa.manifest`), cache d'API du service worker (`pwa.api_cache`), Brotli (`net.brotli`), mesures terrain notées avec les seuils officiels (INP ≤ 200 ms), insights de Lighthouse 13.
- **Garde-fou** : la matrice des routes d'API en anonyme ne tourne que sur un domaine prouvé (même preuve que le test de charge), sinon le pré-vol servirait à repérer le site d'un autre ; les routes à effet (`logout`, `delete`, `publish`, `invite`, `cron`, `send`…) ne sont jamais appelées.
- **Essai sur la production** (10/11/2026, avant ce déploiement) : les contrôles retrouvent seuls les constats SEC-01, PWA-01 et NET-01 de la recette ; 15 pages du sitemap à 200 ; 11 routes d'API en anonyme, toutes en 401 ou 404 ; 34 routes lues dans le routeur (la recette manuelle en comptait 35).
